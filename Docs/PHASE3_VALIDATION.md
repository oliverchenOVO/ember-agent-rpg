## 戰鬥與觀賞

24 個技能有獨立效果：持續傷害、護盾、反擊、脆弱、定身、空間控制區、召喚物清除、治療、淨化及每 Agent 每輪一次的真實復活。劍、弓、杖灌注從實際武器原點發射，元素與技能回饋分離。技能成本、冷卻、灌注、詞綴及 Boss intel 有雙語提示。工坊掉落保證職業可用武器，打造提供較高品質與可選灌注；AI 估價職業、詞綴、法力與灌注。

鏡頭加入進場、階段與死亡焦點、休息區概覽與手動控制優先；音效擴充到 15 個事件與工坊機械環境層。音訊為合成 prototype，沒有完成外部錄音/混音或正式音樂製作。

## 難度與資料

難度分別調整耐久、傷害頻率、預警、空間幾何、移動、階段、資源消耗與協調需求。修正持續傷害每 tick 最少 1 點造成的放大；改善一般撤離窗口，減少無意義立即拆隊；戰鬥 240 秒後增加狂暴壓力，防止永久恢復消耗戰。

原 Phase 2 基線 1000 組全部通關、無個體死亡；調整樣本 100 組 65 通關、35 全滅、0 未終止。調整樣本的 10F 條件通關 84.5%、平均 87.5 秒，顯示 capstone 與恢復需求。這些不是最終樣本。最終 5000 組與編成比較完成後另補。原有 1000 組安全回歸已通過：504 通關 / 496 全滅；crash、softlock、無法推進、無限戰鬥、分隊死鎖與存檔損壞各 0，最大樓層 25。

每層 CSV/JSONL 包含時間、分隊、角色職業/武器、傷害/治療/死亡、品質、技能、藥水、掉落、製作、休息設施與分合隊；分析依 seed 去重。Exposure 平均不是因果強度，不能只據此斷言某職業過強。[資料定義與 authoring](PHASE3_CONTENT_PIPELINE.md)、[難度曲線](DIFFICULTY_CURVE.md)。

## 效能與原生警告

約 31.4 分鐘的中間版本渲染診斷與約 296 秒的最後版本診斷已有分析。60/120 分鐘未完成。資源數有界、GC 仍有配置、暖機後 native memory 增加，不能宣稱零洩漏。

JobTempAlloc 最小對照將重現路徑隔離至 ParticleSystem 退出；相同 Release 未清理兩次各 1 警告，清理/延遲退出兩次均 0。與 Unity 6000.2.0f1 已知問題一致，但未取得引擎內部精確配置呼叫點，也未升級引擎。見 [PERFORMANCE.md](PERFORMANCE.md)。

## 限制與 Phase 4 建議

1. 搬移後先驗證最後 Build，再補完整 30/60/120 分鐘渲染 profile；升級修正粒子生命週期的 Unity patch 並重跑對照。
2. 根據最終 telemetry 的 10F 個體死亡、治療需求與單職業比較校正，不直接放大 HP。
3. 優先補專屬 11–15F，之後逐區完成後十五層，避免把 25 層框架視為完整內容。
4. 用真正 rig / animation、正式 VFX/音樂替換程序組裝與合成音，保留預警可讀性。
5. 補多目標召喚物的獨立 HP、完整控制狀態語意、裝備檢視與更精細 profiler allocation stack。
6. 商業 LLM 串接不是本輪必要交付，現有 gateway 保留；未以真實商業模型做費用與品質驗證。

搬移步驟與必要資料見 [PROJECT_MOVE.md](PROJECT_MOVE.md)。
